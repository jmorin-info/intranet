# Intégrité et antivirus des versions OnlyOffice

Chaque sauvegarde ou restauration crée désormais une `DocumentVersion` distincte. Aucun ancien fichier/version n'est écrasé ni supprimé. Le pointeur est modifié par CAS (version, date, statut et absence de suppression), dans la transaction sérialisable commune aux workflows. Un échec purge uniquement le nouvel upload ; un callback concurrent reçoit `error: 1` afin de demander une nouvelle tentative.

La nouvelle version revient toujours à `DRAFT` et `PENDING`, y compris après une édition d'un document approuvé. Le helper canonique annule les instances/étapes d'approbation et demandes de validation encore en attente, avec journal de l'acteur, dans cette même transaction. Une validation/signature déjà en cours bloque la sauvegarde avant téléchargement. Les décisions historiques sont conservées. Une nouvelle publication exige à nouveau les contrôles GED habituels.

Le scan cible l'identifiant de la nouvelle version ; le CAS existant du scanner empêche un résultat tardif de certifier un autre contenu. Une panne ou absence du scanner ne donne jamais `CLEAN`. Le téléchargement Office revérifie le compte actif, les droits GED canoniques et l'absence de suppression. Il refuse les versions courantes non `CLEAN` et rescane chaque accès à un fichier historique (pas de statut antivirus hérité d'une autre version).

Un état interne `office.active-session.<documentId>` dans AppConfig conserve pendant au maximum 24 h l'origine et la dernière version de la session de coédition. Il n'est valide que si son dernier pointeur est encore courant. Cela permet plusieurs force-saves immuables depuis la même session ; restauration/upload externe invalident cette correspondance. Ce n'est ni un rôle ni une autorisation : les droits sont vérifiés au moment du callback. Les clés de consultation/historique sont distinctes des clés d'édition pour éviter un cache de contenu en cours d'édition sur une consultation figée.

Aucune migration de schéma ni dépendance nouvelle. Les fichiers précédemment écrasés par l'ancien code ne sont pas recréés. Une analyse antivirus indisponible rend la nouvelle version temporairement indisponible, intentionnellement.

Validation locale sous Node 24.22.3, réseau privé systemd : compilation TypeScript sans émission, build backend, 111 suites / 1 614 tests réussis. Les régressions couvrent les force-saves répétés, le chevauchement, un pointeur remplacé par restauration, les conflits de sauvegarde/restauration, la conservation des anciens fichiers, le nouveau statut DRAFT/PENDING, l'annulation des circuits, le scan lié à la nouvelle version, le recalcul du checksum de restauration, les droits révoqués et les refus antivirus. Rapport brut local : `/root/intranet-office-av-full-20261113.log`. Aucun appel à la VM, aucune donnée métier ni fichier de production.
